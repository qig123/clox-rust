 # 语句和全局变量

我们已经成功地将解释器从一个只能处理单个表达式的玩具，扩展为一个能够执行包含语句和全局变量的脚本的解释器。

## 实现思路

### 1. 从表达式到语句

为了支持语句，我们对编译器和虚拟机进行了重大修改。

- **新的 OpCodes**: 我们引入了 `OP_PRINT` 用于打印语句，以及 `OP_POP` 用于丢弃表达式语句在栈上留下的值。
- **编译器更新**: 编译器的 `compile` 函数现在会循环解析一系列声明（`declaration`）。`declaration` 规则可以导向 `var_declaration`（用于变量声明）或 `statement`。`statement` 规则可以进一步导向 `print_statement` 或 `expression_statement`。
- **虚拟机更新**: 虚拟机现在可以处理 `OP_PRINT` 和 `OP_POP` 指令。`OP_RETURN` 不再隐式打印结果，它的职责仅仅是结束执行。

### 2. 全局变量

我们通过引入一套新的指令和数据结构来实现全局变量。

- **新的 OpCodes**:
    - `OP_DEFINE_GLOBAL`: 用于定义一个新的全局变量。
    - `OP_GET_GLOBAL`: 用于获取一个全局变量的值。
    - `OP_SET_GLOBAL`: 用于给一个已存在的全局变量赋值。
- **虚拟机中的全局变量表**: `Vm` 结构体现在包含一个 `globals: HashMap<String, Value>`，它作为全局变量的运行时存储。
- **编译器中的变量处理**:
    - **变量声明**: `var_declaration` 函数负责解析 `var` 语句。它会将变量名作为常量添加到常量池，编译初始化表达式（如果存在），然后发出 `OP_DEFINE_GLOBAL` 指令。
    - **变量访问与赋值**: 解析器现在可以区分变量访问和赋值。当遇到一个标识符时，它会检查下一个 Token。如果是一个 `=`，它会编译右侧的表达式并发出 `OP_SET_GLOBAL`；否则，它会发出 `OP_GET_GLOBAL` 来获取变量的值。

### 3. 错误恢复与同步

为了提供更好的用户体验，我们实现了一个错误恢复机制，使得编译器在遇到错误时不会立即退出，而是能继续解析并报告多个独立的错误。

- **恐慌模式 (Panic Mode)**: 当编译器检测到第一个语法错误时，它会报告错误并进入“恐慌模式”。在此模式下，它会停止报告新的错误，以避免由第一个错误引发的级联错误刷屏。
- **同步 (Synchronization)**: 进入恐慌模式后，编译器会调用 `synchronize()` 函数。该函数会不断丢弃 Token，直到找到一个安全的“同步点”。我们定义同步点为一条新语句的开始（例如 `;` 之后，或 `var`, `if`, `print` 等关键字之前）。
- **恢复解析**: 找到同步点后，编译器会退出恐慌模式，并从该点恢复正常的解析过程。
- **中止执行**: `Compiler` 会记录在整个编译过程中是否发生过任何错误。如果发生过，`compile` 函数最终会返回一个错误，阻止虚拟机执行任何可能已生成的、不完整的字节码。

## `Rc<T>` 与引用循环

目前，我们使用 `Rc<String>` 来管理字符串，这在当前是内存安全的。因为 `String` 是一个“终端”类型，它本身不能持有另一个 `Value`，所以无法构成引用循环。

**潜在风险**: 当我们开始实现更复杂的容器类型时，例如**类实例（Instance）**或**列表（List）**，内存泄漏的风险就会出现。这些容器可以持有对其他 `Value` 的引用，从而可能导致循环依赖。

例如，以下 Lox 代码会创建循环引用：
```lox
class Thing { }
var a = Thing();
var b = Thing();
a.field = b; // a 拥有对 b 的强引用
b.field = a; // b 拥有对 a 的强引用
```
如果 `a` 和 `b` 内部都使用 `Rc` 来持有对方，它们的引用计数将永远无法归零，即使 `a` 和 `b` 这两个变量本身已经离开作用域，它们所占用的内存也无法被回收。

**解决方案**: 当实现这些容器类型时，我们需要引入 `Weak<T>` 来打破引用循环。`Weak<T>` 是 `Rc<T>` 的非拥有（non-owning）伙伴，它允许我们引用一个对象而不增加其强引用计数。通过在循环引用中策略性地使用 `Weak` 指针，我们可以确保数据在不再需要时能够被正确地释放。
